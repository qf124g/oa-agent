## 现状（[index.ts](file:///Users/test/Desktop/food_shop_agent/backend/src/index.ts#L518-L547) 四个清洗函数）

现在做的都是**格式规范化**：

| 函数 | 做了 | 没做 |
|---|---|---|
| `normalizeTerm` | trim | 长度/字符校验 |
| `normalizeSynonyms` | trim、去空、去重 | 数量上限 |
| `normalizeQuestion` | trim、折叠空白 | 噪声/长度/语义 |
| `normalizeAnswer` | 空白返回 null | 长度上限 |

它挡得住 `"  年假 \n"` 这种，挡不住脏内容、重复语义、无意义问题。而 [agent-server 侧](file:///Users/test/Desktop/food_shop_agent/agent-server/src/rag/knowledge-sync.ts) 的 `normalizeQuestion + reportedQuestions` 也只是**进程内精确去重**（"年假怎么申请"和"如何申请年假"会被当成两条）。

## 更完善的方案（分层，从轻到重）

把"清洗"拆成一条**质量门禁链**，而不是几个散函数：

| 层 | 职责 | 落地位置 |
|---|---|---|
| **L1 格式清洗** | trim、折叠空白、去重、全角→半角、大小写统一、控制字符剥离（已有 80%，补全即可） | 现有清洗函数 |
| **L2 内容清洗** | 剥离 HTML 标签、URL、Markdown 标记、emoji/特殊符号 | 现有清洗函数 |
| **L3 质量门禁** | 长度上下限（如问题 2~200 字）、纯噪声拒绝（纯标点/纯数字/纯表情）、语言检测 | 后端提交入口，`BusinessError` 直接拒 |
| **L4 敏感机审** | 敏感/违规词库命中 → 直接拒收或标 `status` 转人工复核 | 后端提交入口 + 词库配置 |
| **L5 语义去重** | 与已审核 FAQ/文档做**向量相似度**比对，超阈值视为重复、拒绝新增并累计计数 | 复用现有 `embedding + VectorIndex`，审核前机审 |
