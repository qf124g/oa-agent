# 异步任务中心 — 验证测试报告

- 验证日期：2026-10-18
- 验证对象：Agent 异步任务中心（任务列表 + 任务详情 + 状态机）
- 验证方式：本地启动三服务，通过 HTTP 调用真实触发 Agent 对话，核对任务记录与状态流转
- 结论：通过（发现并修复 1 个状态机缺陷，异常态 FAILED / 已中断 均已覆盖）

## 1. 概述

本次为该功能新增「异步任务中心」后的首轮端到端验证，覆盖：

1. 读操作任务：无需人工确认，直接完成；
2. 写操作任务：需人工确认，验证 `待确认 → 确认 → 完成` 状态流转；
3. 任务列表 / 详情接口的正确性；
4. 执行时间线是否完整记录每一步；
5. 失败态（FAILED）：异常场景触发 error 事件；
6. 中断态（INTERRUPTED）：客户端执行中提前断开连接。

验证结论为**通过**，并在写操作用例中发现一处状态机缺陷（缺陷编号 D-01），已修复并回归通过；FAILED、INTERRUPTED 两个异常态均补充实现并验证通过。

## 4. 测试用例与结果

| 用例 | 场景 | 预期 | 结果 |
| --- | --- | --- | --- |
| TC-01 | 读操作（查待办） | 任务 DONE，工具 get_my_todos | 通过 |
| TC-02 | 写操作（新建待办） | 任务停留 WAITING_CONFIRM | 失败 → 见 D-01 |
| TC-03 | 写操作重验（修复后）+ 批准确认 | WAITING_CONFIRM → DONE | 通过 |
| TC-04 | 异常确认（错误 confirmId） | 任务 FAILED | 通过 |
| TC-05 | 执行中提前断开连接 | 任务 INTERRUPTED | 通过 |

### 4.1 TC-01 读操作任务

- 请求：`POST /api/chat`，message = `帮我查一下我的待办事项`
- 任务列表返回：

```json
{
  "id": "a9dd4c94-9840-49f3-8a7a-0a99218d618d",
  "title": "帮我查一下我的待办事项",
  "status": "DONE",
  "toolNames": ["get_my_todos"],
  "stepCount": 9
}
```

- 详情时间线（截选）：收到请求 → 模型思考 → 模型回复 → 决策工具 get_my_todos → 调用工具 → 执行成功 → 工具返回 → 第二轮思考 → 纯文本回答。
- 断言：status = DONE，toolNames 含 get_my_todos，stepCount = 9，result 非空。**通过。**

### 4.2 TC-02 写操作任务（暴露缺陷）

- 请求：`POST /api/chat`，message = `帮我新建一条高优先级待办：周五前提交周报`
- SSE 关键事件顺序：

```
confirmation_request  (confirmId=3d97a384..., toolName=create_todo)
done
```

- 实际结果：任务状态被错误置为 `DONE`，预期应为 `WAITING_CONFIRM`。**失败。**

### 4.3 缺陷 D-01 及修复

- **现象**：写操作发出 `confirmation_request` 后，任务未停留在「待确认」，而是被后续 `done` 事件改成了「已完成」。
- **根因**：agent 发出确认请求后会结束当前 SSE 连接（发 `done`），等待用户通过独立的 `POST /api/chat/confirm` 继续；而 `recordEvent` 的 `done` 分支把 `RUNNING` 和 `WAITING_CONFIRM` 一并置为 `DONE`，覆盖了待确认态。
- **修复**：`done` 分支仅将 `RUNNING → DONE`，`WAITING_CONFIRM` 保持不变（见 `agent-server/src/task.ts` 第 157-163 行）。
- **回归**：见 TC-03。

### 4.4 TC-03 写操作重验（修复后）+ 批准确认

- 请求：`POST /api/chat`，message = `帮我新建一条待办：整理团队周会纪要`
- 阶段 1（未确认）：任务状态 = `WAITING_CONFIRM`，任务 id = `d4d8c30d-0f67-40e7-af03-bbf273f9a2f0`，confirmId = `9766da96-3fa8-4bf4-ae7f-1f4eb6bc03e8`。**通过。**
- 阶段 2（批准）：`POST /api/chat/confirm`，approved = true。
- 阶段 3（完成后）：任务状态 = `DONE`，结果含 `待办已创建 ... 待办 ID T008`。
- 详情时间线（完整）：

```
[log]     收到请求 POST /api/chat
[log]     第 1 步：模型思考
[log]     第 1 步：模型回复（流式）→ 决定调用 1 个工具
[log]     第 1 步：决策工具 create_todo（写操作，需确认）
[log]     第 1 步：等待用户确认
[confirm] 新建待办
[log]     收到确认请求 POST /api/chat/confirm
[confirm] 用户已确认执行
[log]     第 1 步：用户已确认 create_todo
[log]     第 1 步：工具返回 create_todo 执行成功
[log]     第 1 步：模型思考
[log]     第 1 步：模型回复 → 纯文本回答
```

- 断言：confirm 续传按 sessionId 正确追加到同一任务；状态从 `WAITING_CONFIRM` 推进到 `DONE`；时间线含确认节点；result 含 T008。**通过。**

### 4.5 TC-04 失败态（FAILED）

- 请求：`POST /api/chat`，message = `帮我新建一条待办：准备周三客户演示材料`
- 走到确认请求后，`POST /api/chat/confirm` 传入**错误 confirmId**（wrong-confirm-id）、approved = true。
- confirm 响应 SSE：

```
data: {"type":"log","title":"收到确认请求",...}
data: {"type":"error","message":"确认请求不存在或已过期"}
data: {"type":"done"}
```

- 断言：任务状态 = `FAILED`。**通过。**

### 4.6 TC-05 中断态（INTERRUPTED）

- 请求：`POST /api/chat`，message = `帮我查一下我的待办，统计总数和优先级分布`，客户端以 `curl --max-time 3` 提前断开（退出码 28）。
- 断言：任务状态 = `INTERRUPTED`，详情时间线含中断节点：

```
[log]   收到请求
[log]   第 1 步：模型思考
[error] 任务已中断（客户端断开连接，执行提前终止）
```

- 结果：**通过。**

## 5. 状态机覆盖情况

| 状态 | 是否覆盖 | 触发路径 |
| --- | --- | --- |
| RUNNING（执行中） | 是 | 任务创建即进入 |
| WAITING_CONFIRM（待确认） | 是 | 写操作触发 confirmation_request |
| DONE（已完成） | 是 | 读操作直接完成；写操作批准后完成 |
| FAILED（失败） | 是 | 确认请求 confirmId 不匹配触发 error 事件 |
| INTERRUPTED（已中断） | 是 | 客户端执行中提前断开连接 |

## 6. 结论

异步任务中心的核心能力已通过端到端验证：任务随对话自动创建、状态随执行流转、执行时间线完整可追、确认续传正确归属同一任务。验证过程中发现并修复 1 个状态机缺陷（D-01），修复后回归通过；五种任务状态（执行中 / 待确认 / 已完成 / 失败 / 已中断）均已覆盖。
