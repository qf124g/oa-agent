# 性能优化与监控方案

> 适用范围：web、agent-sdk、agent-server、backend。
> 原则：先度量、再优化；每次优化给出前后对比数据，杜绝「凭感觉调优」。

---

## 1. 指标基线

### 前端（web / agent-sdk）

| 指标 | 目标 | 测量方式 |
|------|------|---------|
| FCP / LCP | < 1.5s / < 2.5s | Lighthouse（生产构建 + 节流模拟） |
| 首屏 JS 体积 | gzip 后 < 500KB | `vite build` 产物分析 |
| 对话流式渲染帧率 | 长回复滚动 ≥ 50fps | Performance 面板实测 |
| 图表切换布局跳动 | 0（占位与实图同高） | CLS 观察 |
| SVG 画布拖拽帧率 | ≥ 50fps（200 节点内） | Performance 面板实测 |

### 服务端（agent-server / backend）

| 指标 | 目标 |
|------|------|
| 对话首 token 延迟 | < 2s |
| SSE 心跳 | 25s 一次，连接 24h 不断 |
| 知识库检索（embedding + 向量比对） | < 1s |
| 事件回调（backend → agent-server） | 同步 HTTP < 500ms，失败有日志 |

---

## 2. 前端优化手段（本项目已验证有效）

1. **构建层**
   - Vite 手动分包（manualChunks）：react/antd/antv 各自独立 chunk，利用浏览器缓存；
   - KaTeX 字体等重资源按需加载，不打进主 chunk；
   - 路由级懒加载：WorkflowDesigner、Knowledge 等重组件页面 `React.lazy`。
2. **渲染层**
   - 列表：memo + 稳定 key；回调用 useCallback 稳定引用（避免 memo 失效）；
   - 大对象状态用引用替换而非深改；Context value 用 useMemo 保持引用稳定；
   - 流式渲染：Markdown 增量解析，图表只在 JSON 合法后渲染，pending 占位高度一致防 CLS。
3. **SVG 画布**
   - 平移缩放走外层 transform（单矩阵更新），不逐节点改坐标；
   - 节点数量大时：视口裁剪 + 连线简化；filter（阴影/模糊）谨慎使用（逐像素重采样）；
   - 高频事件（mousemove 连线）走 rAF 合帧。
4. **网络层**
   - SSE 单连接复用（心跳 25s），不为每个功能开新连接；
   - 收件箱未读数 10s 轮询，页面隐藏时暂停（visibilitychange）。

---

## 3. 服务端优化手段

1. **知识库 RAG**
   - 文档级增量索引：contentHash 比对，只重算变更文档的向量；删除文档同步清索引；
   - 文本分块 500 字、按句号/分号切长段，避免跨段语义断裂；
   - embedding 批量调用，避免逐块请求。
2. **Agent 循环**
   - 同轮多工具：只读工具先并行执行，写工具入队逐项确认，减少模型往返；
   - 历史消息按 token 预算裁剪，避免上下文无限增长。
3. **连接与内存**
   - 离线消息收件箱每用户上限 100 条，超出淘汰最旧；
   - SSE 连接注册表按 userId 索引，断连立即清理，防句柄泄漏。

---

## 4. 监控与告警

- **前端**：关键页面性能埋点（FCP/LCP/接口耗时 P95）上报；JS 错误、接口失败、SSE 异常断连三类告警；
- **服务端**：agent-server 结构化日志（步骤号、任务描述、工具决策、返回摘要）——前端日志面板同步展示，便于复现问题；
- **发布门禁**：新版本性能指标对比基线劣化 > 10% 时阻塞发布，先优化再上。

---

## 5. 内存泄漏排查 SOP（对话组件/画布重点）

1. Chrome Memory → Heap Snapshot：打开功能 → 销毁 → 强制 GC → 再快照 → comparison 视图找新增的 detached DOM / 未释放实例；
2. Performance Monitor：反复开关功能，JS Heap 与 DOM Nodes 只增不减即为泄漏；
3. 重点检查：EditorView/simulation 是否 destroy、Observer 是否 disconnect、rAF 是否 cancel、全局/模块级变量是否缓存实例、React ref 卸载是否置空。

## 6. 优化案例库（持续沉淀）

| 案例 | 根因 | 方案 | 效果 |
|------|------|------|------|
| 端口连线命中率低 | 视觉圆 r=7 可点区域太小 | 透明命中圈 r=14 + pointer-events: all | 命中率显著提升 |
| 拖拽连线落点识别失败 | 橡皮筋虚线盖住端口 | 拖拽层压到图层最下方 | elementFromPoint 正常 |
| 图表流式渲染跳动 | 原始文本直接闪现 | pending 占位同高 + 解析后瞬时替换 | CLS ≈ 0 |
| Node 16 构建报错 | Vite 5 / pdf-parse 需 Node ≥ 20 | .nvmrc 锁 Node 20 | 构建稳定 |
