# 协作与技术攻坚机制

> 适用范围：food_shop_agent 研发团队。
> 目标：任务可追踪、阻塞有出口、经验能沉淀。

---

## 1. 模块 Owner 制

| 模块 | 职责范围 |
|------|---------|
| web 主站 | 页面、路由、业务组件、接口层 |
| agent-sdk | 对话组件、SSE 客户端、图表渲染、确认卡片 |
| agent-server | agent 循环、工具执行、skills、RAG、SSE 推送、任务中心 |
| backend | 业务 API、鉴权、数据存储、领域事件回调 |

- 每个模块 1 名 Owner：负责该模块的方案评审、代码终审、线上问题第一响应；
- 跨模块改动（如新增一种领域事件，需 backend 发、agent-server 推、sdk 展示三方联动）：由发起方写联动方案，三方 Owner 会签后开工。

---

## 2. 日常协作节奏

- **每日站会**（15min）：昨天进展 / 今天计划 / 阻塞项——阻塞项当场指定协助人；
- **Code Review**：所有提交过 PR 评审；核心模块（agent-loop、session、auth、确认队列）必须模块 Owner 审；
- **周会技术复盘**：本周踩坑、AI 使用案例、性能数据回顾；结论进知识库；
- **文档即交付**：每个需求交付物 = 代码 + 关键设计说明（复杂逻辑必须带，如多写工具确认队列的设计约束）。

---

## 3. 跨端/跨服务联动约定（本项目高频场景）

1. **新增领域事件**（如 xxx.created）：
   - backend：写操作成功后同步 HTTP 回调 agent-server（带 shared secret）；
   - agent-server：按规则广播（如 approval.submitted 广播给在线管理员、排除申请人），收件箱落库（每用户上限 100）；
   - agent-sdk/web：SSE 接收 → 结构化 quick actions（label + sendText）展示，未读数角标更新；
   - 自环规则：source 为 agent 且 target 是操作者本人 → 不通知。
2. **新增 Agent 能力**：优先评估能否做成 skill（agent-server/skills/ 下加 SKILL.md），不动核心循环；确定性计算做成 scripts/*.mjs，走 `run_skill_script` 本地执行。
3. **接口先行**：前后端联调前先定契约（字段、错误码），mock 先行，禁止「先写前端再等后端」。

---

## 4. 技术攻坚升级机制

- **24h 规则**：同一问题卡 24h 未解决 → 升级到模块 Owner；再 24h → 组织 2-3 人专项攻关；
- **攻关输出**：必须产出《问题报告》，四要素齐全——现象 / 根因 / 方案 / 预防措施，进知识库；
- **技术预研（Spiking）**：新技术/新方案先用 1-3 天小范围验证（如多写工具确认队列先写演示脚本验证再合入），验证报告评审通过后才进正式需求；
- **禁止事项**：不折中方案凑数（折中=没想清楚）、不为兼容假想场景加兜底、不绕过根因打补丁。

---

## 5. 线上问题响应

1. **响应**：告警/反馈后 30min 内确认现象与影响面；
2. **止损**：能回滚先回滚，能降级先降级，再修根因；
3. **定位**：服务端看结构化日志（步骤号/工具决策/返回摘要），前端看控制台最终响应与 SSE 事件流；
4. **复盘**：24h 内出复盘报告，更新监控或检查清单，防止同类问题二次发生。

> 注意：backend 为内存存储，重启即丢运行时数据（todos/approvals/employees 恢复 seed，密码重置为 123456）——排查线上问题时先确认是否刚重启过。
